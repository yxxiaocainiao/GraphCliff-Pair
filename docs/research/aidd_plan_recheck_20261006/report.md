## 修订后的有限下一步：先证据条件，再算法

保留用户8—12周算法论文目标、唯一风险核心、90fit/100GPUh上限、强基线与必需忠实解释；不自动切换评测论文、不承诺二区。此前三个算法问题仍是候选问题，不升格为原课题的三个研究内容。

1. **联合依赖可行性。** 只对现三任务、现开发结构，先审查既有RDKit单切片段实现的边定义/核心限制/默认截断/无手性约定。固定关系后检查canonical+Murcko+MMP联合组件、最大组件与各角色最低独立组件是否可能满足。每任务最多20 CPU分钟，总60分钟，0fit/0权重推理；遇截断/超时标不完整，不删除边或拆大组件救结果。开发结构的结果不能冒充完整30任务或含官方test的确认样本量。
2. **时间/质量数据清单。** 先核验CARA版本、数据许可、schema、逐记录日期与assay/端点及与三靶点对应；只查元数据，当前不下载全量或评价预测。无可靠日期就只称assay外补充，若另查ChEMBL/Papyrus，最多一个可核验来源，不无限换数据集。
3. **算法贡献闸门。** 从实际依赖/迁移失效提出至多1个有精确运算、区别最近方法、可复用及低成本反证的核心。不得把联合图拆分或数据清洗本身当方法贡献。不具备条件继续维持具体路线停止，并报告原PDF复核尚未完成，而不是“全部问题走不通”。
4. **只有条件成立才冻结新实验。** 训练活性置换必须按折训练参考重算粗糙度（基础模型/点预测/风险监督/eval真值固定，不能把query y搬进去），与M28预算分开；相关日期验证、OOF角色、强基线、AURC及解释规则先定义再计预算。PDF100置换/120GPUh不自动覆盖用户的现90fit/100GPUh计划，本轮无额外fit授权或执行。
